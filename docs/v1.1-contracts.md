# v1.1 implementation contracts / 实现契约

Status: implemented research contracts, 2026-11-03. Python 3.9+, standard library only.
Runtime package: `power_trading_agent`. All timestamps are offset-aware ISO 8601;
delivery hours use +08:00, intervals [start, end). Energy is MWh, price CNY/MWh.
All outputs remain research-only. No exchange execution or certified Guangdong settlement.

## Shared contracts

- `contracts.ValidationError(code, message)` exposes `.code`; inherits ValueError.
- `contracts.parse_time(value)` returns aware datetime, rejects naive timestamps.
- `contracts.digest(obj)` is SHA256 over canonical sorted JSON (no NaN).
- `contracts.number(value, field, minimum=None)` validates a finite non-bool numeric.
- `contracts.hours(target_date)` returns exactly 24 ISO +08:00 hour starts.
- `contracts.curve(values, name, nonnegative=False)` validates exactly 24 finite numbers.

## Portfolio / 组合台账

`portfolio.Ledger(path)` is a context manager (SQLite; close on exit).
`record_event(event)` returns bool: true inserted, false exact duplicate; conflicting
content under same `(portfolio_id,event_id,revision)` is rejected.
Event keys: portfolio_id, event_id, revision (positive integer), kind,
available_time, start, end, status (confirmed/pending/cancelled), source.
Kinds: trade, intent, declaration, customer_event.
trade/intent/declaration: `hourly_mwh` (constant MWh per covered hour, >=0).
trade also `price_cny_per_mwh` (finite, may be negative).
customer_event: `customer_id`, `load_multiplier` (>=0), `confirmed` status required
to affect calculations. Multipliers are scoped to customer, not whole portfolio.
Revisions retain history; latest eligible revision as of origin supersedes older,
including cancelled. Scope changes (portfolio/kind/customer) are rejected.
`state(portfolio_id,target_date,as_of)` returns a dict with 24-point `holdings_mwh`,
`holding_cost_cny`, `intents_mwh`, `declarations_mwh`, `customer_events`, `event_refs`,
and `state_id`; future events excluded; pending and cancelled not executed holdings.

Task APIs: `start_run(task_id,input_hash)` returns generation integer, persists new
generation; `finish_run(task_id,generation,input_hash,result)` rejects stale generations.
`select_plan(task_id,generation,plan_id,plan_hash)` binds a selection to completed run.
`get_run(task_id)` returns state and result (including generation and input_hash).
`cancel_run(task_id)` persists cancellation; future start_run rejects cancelled tasks.

## Economics / 研究结算

`economics.settlement(q,l,da,rt,holdings,holding_cost,rule)` returns dict:
`total_cost_cny`, `energy_cost_cny`, `fee_cny`, `hourly_cost_cny`.
Synthetic physical forward convention: cost = holding_cost + (Q-H)*DA + (L-Q)*RT
+ abs(Q-L)*deviation_fee_cny_per_mwh. This is an explicitly synthetic fee adapter,
not actual Guangdong settlement; Q is total day-ahead coverage, H fixed physical
forward delivery. All inputs 24 points. rule requires `rule_id`, `scope=synthetic`,
`price_basis=user_side`, `currency=CNY`, `deviation_fee_cny_per_mwh>=0`.

`economics.make_plans(f,da,rt,config)` returns list of dicts with name, k, q.
Config: k_min, k_max (must enclose 1), adjustment, spread_threshold (>=0).
Must include `baseline` (k=1), `spread_rule` (sign-based), `bounded_rule`
(smaller adjustment); all decisions use forecast prices only.
`economics.evaluate_plans(plans,scenarios,holdings,holding_cost,rule,risk_budget)`:
scenarios dict: kind=stress|probabilistic, scenario_set_id, calibration_status,
items=[{scenario_id,l,da,rt,weight?}]. Stress has no expected/CVaR/probability metrics.
Probabilistic requires calibration_status=validated, nonnegative weights summing 1;
full-day losses vs baseline, weighted CVaR90 with fractional tail mass.
Risk budget None means needs_risk_budget, never auto-select; risk_budget>=0 is
max allowed worst-case incremental loss for stress, CVaR90 for probability.
Return per-plan costs, increments, worst_loss_cny, risk_status and metrics as justified.
`economics.replay_metrics(rows)` summarizes chronological realized daily records
with date, group, baseline_cost_cny, candidate_cost_cny; reports incremental net gain,
loss-day fraction, worst day, cumulative max drawdown and group sample counts.

## Snapshot / 快照

`data.build_snapshot(bundle,target_date,origin)` returns selected 24-point
`f,da,rt`, `input_snapshot_id`, `record_refs`, `price_basis`, target_date, origin,
portfolio_id. Bundle records: record_id, revision, source, available_time, issue_time,
received_at, target_time, metric=load_forecast|da_forecast|rt_forecast, value, unit,
price_basis (prices must user_side). Latest eligible revision only; conflicting
duplicates rejected; all 72 cells required. Target-day actuals are never used here.
`data.actual_curves(bundle,target_date)` accesses separate `actuals` ONLY for scoring.

## Public runner / 运行入口

`python -m power_trading_agent demo --output <new-directory>` runs a synthetic
multi-day replay, creates report.md, results.json, hourly.csv, ledger.sqlite3,
frozen input.json, manifest.json; repeated existing output is rejected.
`python -m power_trading_agent run --input <bundle.json> --output <new-directory>`.
`python -m power_trading_agent benchmark --output <new-directory>` runs independent
acceptance cases. `tools` returns bounded tool descriptors; `tool --request <json>`
dispatches validate_input / portfolio_state / evaluate_day to the same services.
No LLM or credentials required for offline baseline. External LLM hosting remains optional.

`resume --output <directory>` verifies archived input and unchanged runtime source hash,
then reuses completed generations and restarts incomplete ones. `verify` checks file hashes,
input/result provenance, independent synthetic arithmetic, and unique complete CSV hours.
`tool --request` takes a JSON file (or `-` for stdin), never raw shell commands.
The tools are validate_input, portfolio_state, evaluate_day, parse_customer_event.
The text parser accepts only `YYYY-MM-DD HH:00 至 YYYY-MM-DD HH:00 停产/停工`
and always stages pending confirmation; relative dates, negation, revocation and other
wording return needs_clarification. This is not general LLM understanding.

For multi-customer snapshots, bundle.customers is a unique roster and each load_forecast
record has customer_id. Every customer must have all 24 cells. Events modify only that
customer's curve, once, before Q=kF; overlapping confirmed events are rejected.

The probability interface validates the caller's calibration_status assertion, weights,
and complete-day shape; it does not fit or independently certify calibration models.
All results remain research_only. Default runner scenarios are stress, without weights.

## Acceptance / 验收

At least 30 named independent cases, with expected values/status outside runtime.
Include time leakage, units, missing data, conflicting revisions, duplicate trades,
cancel/revise events, pending intent separation, F/L/Q distinction, fees, weighted tail,
stress/probability distinction, stale completion, version-bound selection and restart.
Tests create disposable files only under caller TMPDIR (managed in development).

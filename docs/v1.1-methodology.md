# v1.1 方法与适用范围 / Methods and scope

[返回首页 / README](../README.md) · [接口契约 / Contracts](v1.1-contracts.md)

日期 / Date: **2026-11-03**

v1.0 是业务架构与实施基线；v1.1 将其中一个日前场景实现为可在本地运行的研究闭环：冻结输入、读取组合状态、生成候选、计算压力结果、事后评分及留存证据。完整的 v1.0 蓝图仍包括后续工作，不能把本版本视为全部实现。

v1.0 defines the architecture and implementation baseline. v1.1 implements one local day-ahead research workflow: freeze inputs, read portfolio state, generate candidates, calculate stress results, score against later actuals, and retain evidence. The broader v1.0 blueprint still contains future work.

## 1. 数据、时间与数量 / Data, time and quantities

每个目标日有24个小时，时区为 UTC+08:00。电量单位为 MWh，价格为 CNY/MWh，金额为 CNY。缺失和非有限数值被拒绝。输入快照只选择信息截点前可得的来源版本；目标日实际数据由事后评分入口读取，不能参与候选生成。

Each delivery day contains 24 hours in UTC+08:00. Energy is MWh, prices are CNY/MWh, and money is CNY. Missing or nonfinite values are rejected. Snapshots select source revisions available at the information cutoff; target-day actuals are read separately for scoring and do not generate candidates.

| 符号 / Symbol | 定义 / Definition |
| --- | --- |
| F | 当前发布并经过已确认客户事件修正的预测电量 / Published forecast energy after confirmed customer-event adjustments |
| L | 情景电量，或评分时使用的实际电量 / Scenario energy, or realized energy used for scoring |
| Q=kF | 候选日前总覆盖量 / Candidate total day-ahead coverage |
| H | 已成交的实物远期交割电量 / Executed physical forward delivery |
| B | H 对应的已购电成本 / Purchase cost corresponding to H |
| DA、RT | 同一用户侧口径的日前、实时价格 / Day-ahead and real-time prices on the same user-side basis |
| S=RT−DA | 日前实时价差 / Real-time minus day-ahead spread |

组合台账分别保存成交、采购意图、申报和客户事件；采购意图不计入已成交 H。候选 Q 也不代表交易平台已经接收的申报。一个客户的事件只调整该客户负荷，避免将停工影响重复施加到策略系数。

The ledger separates executed trades, purchase intentions, declarations, and customer events. Intentions do not enter executed holdings H. A candidate Q is not evidence of a platform-accepted declaration. Customer events affect that customer's forecast before strategy coefficients are applied.

## 2. 合成结算适配器 / Synthetic settlement adapter

本版实现的逐时成本为：

The implemented hourly cost is:

```text
C[h] = B[h] + (Q[h] − H[h]) × DA[h]
       + (L[h] − Q[h]) × RT[h]
       + |Q[h] − L[h]| × deviation_fee
daily_cost = sum(C[h], h=0…23)
incremental_gain = baseline_daily_cost − candidate_daily_cost
```

这是假定实物远期已覆盖 H 的合成研究账式，Q 已包含 H，因此日前新增购电项使用 Q−H。允许负电价和有正负方向的结算项。偏差费用参数必须非负；规则必须声明 `scope=synthetic`、`price_basis=user_side` 和 `currency=CNY`。运行入口还检查规则来源与覆盖目标日的有效期。

This synthetic accounting convention assumes physical forwards already cover H, and Q includes H; the incremental day-ahead leg therefore uses Q−H. Negative electricity prices and signed settlement legs are supported. The deviation fee must be nonnegative. Rules must declare `scope=synthetic`, `price_basis=user_side`, and `currency=CNY`; the runner also checks source information and date validity.

**该公式不是广东现行结算规则的认证实现。** 它不覆盖零售收入、正式偏差收益回收、全部税费或完整经营利润。正的 `incremental_gain` 表示在相同持仓、价格、负荷和费用条件下比基准少花钱，不能直接解释为公司的总利润。

**This is not a certified implementation of current Guangdong settlement rules.** It does not cover retail revenues, formal revenue-recovery provisions, all taxes and fees, or total operating profit. Positive `incremental_gain` means a lower cost than the baseline under identical holdings, prices, load, and fees; it is not company-wide profit.

## 3. 三种透明策略 / Three transparent policies

策略只读取预测价差 `forecast_RT − forecast_DA`。设配置调整幅度为 a、价差门槛为 t，价差大于 t 时方向为 +1、小于 −t 时为 −1，其余为0；结果截断到配置的 `[k_min,k_max]`，且范围必须包含1。

Policies read only `forecast_RT − forecast_DA`. Let a be the configured adjustment and t the spread threshold. Direction is +1 above t, −1 below −t, and zero otherwise. Coefficients are clipped to configured `[k_min,k_max]`, which must contain 1.

| 策略 / Policy | 系数 / Coefficient | 用途 / Purpose |
| --- | --- | --- |
| `baseline` | k=1 | 相同 F 下的固定对照 / Fixed comparison for the same F |
| `spread_rule` | k=clip(1+direction×a) | 完整配置幅度 / Full configured adjustment |
| `bounded_rule` | k=clip(1+direction×a/2) | 较小幅度的对照 / Smaller-adjustment comparison |

这些是规则候选，不是训练模型、数学优化器或全局最优解。系数范围是研究配置，不代表正式政策允许区间。比较入口核对每个候选的 Q=kF，防止不同预测被混入同一策略对照。通过风险检查也不会自动选择或执行方案。

These are rule-based candidates, not trained models, mathematical optimizers, or globally optimal solutions. Coefficient bounds are research settings, not certified market-policy limits. Evaluation verifies Q=kF for every candidate so different forecasts cannot silently enter one policy comparison. Passing a risk check does not select or execute a plan.

## 4. 压力与概率情景 / Stress and probability scenarios

默认演示及运行流程使用**压力情景**：每条情景包含完整24小时的 L、DA、RT。输出条件成本、相对基准增益与所提供情景中的最大增量损失。压力情景不接受概率权重，不输出期望收益、亏损概率或 CVaR，也不声称覆盖了全部可能的极端情况。

The default demo and runner use **stress scenarios**, each with full-day L, DA, and RT curves. Outputs are conditional costs, gains relative to baseline, and the largest incremental loss among supplied scenarios. Stress scenarios reject probability weights and provide no expected gain, loss probability, or CVaR. They are not claimed to cover every possible extreme outcome.

计算服务另提供概率情景接口：要求 `calibration_status=validated`，权重非负且总和为1，并校验完整日曲线。这个状态是调用者声明，**程序不会独立证明概率已校准**；调用者需另行提供时序隔离的校准样本、方法和验证证据。本版没有训练或认证概率模型，默认演示没有启用该接口。

The calculation service additionally accepts probabilistic scenarios with `calibration_status=validated`, nonnegative weights summing to one, and complete daily curves. This status is a caller declaration: **the software does not independently prove calibration**. Callers must separately establish temporally isolated calibration data, methods, and evidence. This release does not train or certify a probabilistic model, and the default demo does not use this interface.

概率模式先计算整日相对损失 `loss=C_candidate−C_baseline`，再从最大损失起累计最差10%的概率质量。跨越10%边界的情景只计入需要的权重部分，最后除以0.1，得到加权 CVaR90。例如损失100、20、0，权重0.05、0.10、0.85，则 CVaR90=(0.05×100+0.05×20)/0.1=60。

Probabilistic mode first computes full-day relative loss `loss=C_candidate−C_baseline`. It then accumulates the worst 10% probability mass, starting with the largest loss, uses only the needed fraction of a boundary scenario, and divides by 0.1. For losses 100, 20, and 0 with weights 0.05, 0.10, and 0.85, weighted CVaR90 is `(0.05×100+0.05×20)/0.1=60`.

CVaR使用有符号损失；最差尾部仍盈利时可以为负，不逐小时相加。`worst_loss_cny` 则将最大增量损失截断至不小于0。风险金额未提供时返回 `needs_risk_budget`；提供时，压力模式比较最大增量损失，概率模式比较 CVaR90。`within_budget` 仅表示对应指标满足本次配置，所有结果仍为研究状态。

CVaR uses signed losses and may be negative when even the worst tail remains profitable; hourly CVaRs are not summed. `worst_loss_cny` floors the maximum incremental loss at zero. A missing risk budget yields `needs_risk_budget`. Otherwise, stress mode compares its worst incremental loss with the budget, and probabilistic mode compares CVaR90. `within_budget` only describes that configured check; every result remains research-only.

## 5. 历史回放与分组 / Replay and grouping

演示数据、持仓、规则和预算均为虚构。演示预测使用截点前已经可得的七个历史日的逐时均值，保存来源时间与预测版本；这是简单基线，不是经真实业务验证的预测模型。候选生成完成后，再用目标日实际标签评分。

Demo data, positions, rules, and budgets are invented. Demo forecasts use hourly means from seven historical days already available before the cutoff, with provenance and forecast-version records. This is a simple baseline, not a model validated on real business data. Target-day actual labels are used only after candidates have been generated.

回放要求日期唯一并严格递增。按每个固定策略输出总增量收益、日均增量收益、历史亏损日占比、最差日和累计增量收益最大回撤；回撤从累计收益0开始计算。分组同时报告样本量，同一组的回撤按该组日期子序列计算，不是完整日历上的连续投资组合回撤。

Replay dates must be unique and strictly increasing. Each fixed policy reports total and mean daily incremental gains, the historical fraction of losing days, worst day, and maximum drawdown of cumulative incremental gain, starting from zero. Groups report sample counts; group drawdowns use that group's date subsequence, not a continuously traded full-calendar portfolio.

分组标签只用于事后评价，不能作为候选生成时已知的特征。合成尖峰标签尤其不代表系统提前预测出了尖峰。历史亏损日占比是样本频率，不是对未来的概率预测。

Group labels are for retrospective evaluation, not presumed ex-ante features. In particular, a synthetic-spike label does not mean the system predicted a spike. Historical losing-day fractions are sample frequencies, not future probability forecasts.

## 6. 借鉴来源与后续工作 / References and remaining work

本仓库本次新增运行代码为原创实现，借鉴下列项目的方法与职责划分，没有复制它们的代码或市场规则。本次对外部项目进行的是资料和代码阅读，没有在本地运行这些工具，也没有据此验证广东市场效果。

The runtime code added in this release is an original implementation informed by the following methods and responsibility boundaries. It does not copy their code or market rules. External references were reviewed through documentation and code reading; these tools were not run locally, and no Guangdong-market performance was established from them.

本版尚未实现真实数据模型训练、概率模型校准、自由文本的大模型理解、DeepSeek Harness 宿主集成、生产交易平台连接及正式结算认证。结构化工具入口和可运行基线为这些后续工作保留接口；单元测试或合成回放通过，不替代真实业务验收。

Real-data model training, probabilistic calibration, free-form LLM understanding, DeepSeek Harness host integration, production trading-platform connections, and certified settlement remain future work. Structured tools and the runnable baseline provide integration points. Passing unit tests or synthetic replay does not replace real-business acceptance.
